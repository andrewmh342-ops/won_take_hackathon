# SPEC 수정안: R5 시연 시나리오 보완 (맥락 기억·중복 정리)

> 상태: **승인됨(2026-10-27)**. SPEC.md R5 "R5 시연 시나리오 보완" 절과 4장 작업 33~37로 옮겼다. 기준은 SPEC.md다.
> 작성: 2026-10-27, 사용자가 실제 시연 흐름을 해 본 뒤 요청.

## 0. 목적

WON테이크가 AI를 쓰는 이유는 **같은 질문이라도 고객의 상태·행동 기록·이전 대화에 따라 다른 해결 순서를 만든다**는 점이다. 시연에서는 이것이 한 고객의 두 장면으로 이어져 보여야 한다.

- 1막: 고객이 일본 여행을 준비한다.
- 2막: 같은 고객이 나중에 "카드 잃어버렸어"라고 말한다. AI는 1막에서 알게 된 여행 정보(일본·출국일)와 1막에서 한 일(트래블카드 해외결제를 켬, 엔화 환전 신청)을 기억한 채로 해결 순서를 만든다.

## 1. 시연 시나리오 (고객 A)

| 막 | 고객의 말 | 기대하는 원테이크 단계 |
|---|---|---|
| 1막 | "나 일본 여행 가" | ① 출국일 확인 → ② 쓸 수 있는 트래블카드 확인 → ③ 트래블카드 해외결제 켜기 → ④ 환전 신청(엔화 환율과 원화 금액을 같은 화면에서 확인) → 마무리 |
| 2막 | "나 카드 잃어버렸어" | ① 잃어버린 카드 확인 → ② 카드 정지(분실신고) → ③ 새 카드 재발급 → ④ 남은 카드 중 한 장의 해외결제 켜기 → 마무리. 나라·출국일은 다시 묻지 않는다. |

2막에서 보여 줄 차이:
- 트래블카드를 잃어버렸으면, 남은 카드(해외결제 꺼짐) 중 한 장을 켜는 단계가 생긴다. 출국이 가까우면 "새 카드는 출국 뒤에 올 수 있어요"를 알려 준다.
- 다른 카드를 잃어버렸으면, 트래블카드는 1막에서 이미 켜 두었으므로 해외결제 단계가 생기지 않는다.

## 2. 지금 시연에서 생기는 문제와 원인

| # | 문제 | 원인 |
|---|---|---|
| 1 | 2막에서 "어느 나라로 가세요?"를 다시 묻는다 | 1막 플랜에서 알게 된 나라(엔화)를 가상 상태에 저장하지 않는다. 출국일만 입력받을 때 저장된다. AI 입력의 `customer.trip.country`가 비어 있어 AI가 다시 묻는다. |
| 2 | 1막에서 한 일(환전 신청 등)을 2막의 AI가 모른다 | AI 입력에는 고객 상태 모양만 있다. 환전 신청 내역과 이전 플랜에서 끝낸 업무가 들어가지 않는다. |
| 3 | 남은 카드를 켜는 장면이 나오지 않는다 | 고객 A의 신용카드·체크카드가 처음부터 해외결제 켜짐이다(`profiles.json`). |
| 4 | 환율 확인에서 환전 신청을 한 뒤 환전 신청 단계가 또 나온다 | 환율 확인과 환전 신청이 같은 통화로 각각 들어간다. 환율 화면에도 [이 금액으로 환전 신청하기] 버튼이 있다. |
| 5 | 같은 카드에 "해외에서 쓸 수 있는지 확인"과 "해외결제 켜기"가 둘 다 나온다 | 대체 결제 수단 확인과 해외결제 설정이 같은 카드에 각각 들어간다. 서버가 합치지 않는다. |
| 6 | 해외결제 켜기가 카드마다 여러 개 나온다 | AI(모의 포함)가 해외결제가 꺼진 카드마다 블록을 넣는다. 해외에서 쓸 카드는 한 장이면 된다. |
| 7 | 1막에서 출국일을 묻지 않는다 | 모의 AI가 분실이 있거나 트래블카드가 없을 때만 출국일을 묻는다. |

## 3. 요구사항 ("~하면, 시스템은 ~한다")

### 3.1 여행 정보 기억
- 플랜에 통화가 있는 블록(환율 확인·환전 신청, 지원 통화)이 들어가면, 시스템은 그 통화의 나라를 고객의 여행 나라로 저장한다. 고객이 정보 확인에서 나라를 답해도 저장한다(지금과 같음).
- 이미 저장된 여행 나라·출국일은 AI 입력 `customer.trip`에 넣는다. 이미 아는 정보를 묻는 정보 확인 블록은 서버가 버린다(지금 규칙 유지).
- 고객이 환전을 신청하면, 시스템은 AI 입력 `customer.cash`에 신청한 통화 목록을 넣는다. 금액은 넣지 않는다(가명화).

### 3.2 이전 플랜을 AI가 이어받기
- 새 질문으로 플랜을 만들 때, 시스템은 같은 세션의 최근 플랜 2개를 요약해 AI 입력 `recentPlans`에 넣는다. 항목: 사건 이름, 끝낸 업무(`blockId@카드 ref`), 남은 업무. 카드는 ref만 쓴다.
- 지침에 "이전 플랜에서 끝낸 업무는 다시 넣지 않는다. 이전 대화·플랜에서 확인된 정보는 다시 묻지 않는다"를 넣는다.

### 3.3 해외결제 기본값
- 모든 시연 고객(A·B·C)의 모든 카드는 처음에 해외결제 꺼짐이다.

### 3.4 중복 단계 정리 (서버 조립 규칙)
- 같은 통화의 환율 확인과 환전 신청이 함께 오면, 시스템은 환전 신청 하나만 남긴다. 환전 신청 화면이 환율과 원화 금액을 함께 보여 준다. 남긴 블록의 필수/선택은 둘 중 높은 쪽(필수 우선)이다. 뺀 환율 확인은 "넣지 않은 일"에 "환전 화면에서 환율을 함께 보여 줘요"로 남긴다.
- 같은 카드에 대체 결제 수단 확인과 해외결제 설정이 함께 오면, 시스템은 하나만 남긴다. 그 카드의 해외결제가 꺼져 있으면 해외결제 설정, 켜져 있으면 대체 결제 수단 확인이다.
- 해외결제 설정 블록이 여러 카드에 오면, 시스템은 AI 순서상 첫 카드만 필수로 두고 나머지는 선택으로 낮춘다. 해외에서 쓸 수 있는 카드(사용 가능·해외결제 켜짐)가 이미 있으면 해외결제 설정은 모두 선택이다.
- 플랜에서 들어간 환율 조회 화면에는 [이 금액으로 환전 신청하기] 버튼 대신 [다음 단계로]를 보여 준다. 메뉴로 직접 들어가면 버튼을 그대로 보여 준다.

### 3.5 여행 준비 순서
- 여행 플랜에서 출국일을 모르면, 시스템은 정보 확인(출국일)을 보호 조치 다음 첫 단계로 둔다. 보호 조치가 없으면 맨 앞이다.
- AI 지침: 해외에서 쓸 카드는 한 장이면 된다. 사용 가능한 트래블카드가 있으면 그 카드, 없으면 남은 카드 중 한 장의 해외결제를 켠다.

## 4. 규칙 예시표 (한 행 = 테스트 하나)

| 상황 | 결과 |
|---|---|
| 1막 플랜에 `fx-exchange-apply(JPY)` | 여행 나라 "일본" 저장, 2막 AI 입력 `customer.trip.country = 일본` |
| 2막 AI가 정보 확인(나라)을 넣음 | 서버가 버림, "넣지 않은 일"에 "이미 확인한 정보예요" |
| 1막에서 출국일 답함 → 2막 | 출국일 질문 없음, `trip.daysUntilDeparture` 전달 |
| 1막에서 JPY 환전 신청 | 2막 AI 입력 `customer.cash = [JPY]`, 금액 없음 |
| 1막 플랜 끝 → 2막 질문 | `recentPlans`에 1막 사건·끝낸 업무(`overseas-payment-check@card-2` 등) |
| 시연 고객 A·B·C 시작 상태 | 모든 카드 해외결제 꺼짐 |
| 환율 확인(JPY, 필수) + 환전 신청(JPY, 선택) | 환전 신청(JPY, 필수) 하나 |
| 환율 확인(JPY) + 환전 신청(USD) | 둘 다 남김(통화가 다름) |
| 같은 카드에 대체 결제 수단 확인 + 해외결제 설정, 해외결제 꺼짐 | 해외결제 설정 하나 |
| 같은 카드에 둘 다, 해외결제 켜짐 | 대체 결제 수단 확인 하나 |
| 해외결제 설정이 card-1·card-3 두 장 | card-1 필수, card-3 선택 |
| 해외에서 쓸 수 있는 카드가 이미 있음 + 해외결제 설정 | 선택 |
| 플랜에서 들어간 환율 조회 화면 | 환전 신청 버튼 없음, [다음 단계로] |
| 메뉴로 직접 들어간 환율 조회 화면 | 환전 신청 버튼 있음 |
| 여행 플랜, 출국일 모름, 보호 조치 없음 | 정보 확인(출국일)이 첫 단계 |
| 여행 + 분실 플랜, 출국일 모름 | 분실신고 다음이 정보 확인(출국일) (지금 규칙 유지) |
| 2막: 트래블카드 분실, 남은 카드 해외결제 꺼짐 | 남은 카드 한 장의 해외결제 설정(필수) |
| 2막: 신용카드 분실, 트래블카드는 1막에서 켜 둠 | 해외결제 설정 없음 |

## 5. 바뀌는 데이터·API·AI 입력

| 대상 | 변경 |
|---|---|
| `profiles.json` | A·B·C 모든 카드 `overseasPayment: false` |
| `CustomerShape` (AI 입력) | `cash: [통화 코드]` 추가. `trip.country`는 저장된 나라로 채움 |
| `Context` (AI 입력) | `recentPlans: [{events, done[], pending[]}]` 추가, 최대 2개, ref만 |
| `ProfileStore.CustomerState` | 플랜 조립 때 통화 → 나라 저장(JPY 일본, USD 미국, EUR 유럽, CNY 중국) |

| `FxRateScreen` | 플랜에서 들어오면 환전 버튼 대신 [다음 단계로] |
| `chat-system.txt` | 3.2·3.5 지침 추가, 시연 사건의 정답 순서는 쓰지 않는다(기존 원칙 유지) |
| `FakeAiClient` | 모의 시연용: 여행이면 출국일을 모를 때 먼저 묻기, 해외결제 설정은 한 장만, 분실 뒤 남은 카드는 해외결제 설정 하나 |

## 6. 기존 테스트 기대값이 바뀔 것 (구현 때 보고)
- 해외결제 기본값이 꺼짐으로 바뀌면서 "해외결제가 켜진 카드는 설정 블록을 버린다", "해외 결제 수단: 확보(card-1)" 같이 card-1·card-3이 켜져 있다고 가정한 테스트는 그 카드를 테스트 안에서 켜도록 바꾼다.
- 환율 확인 + 환전 신청이 함께 나오던 플랜 테스트는 환전 신청 하나로 바뀐다.
